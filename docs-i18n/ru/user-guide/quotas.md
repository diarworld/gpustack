# Квоты { #quotas }

Вкладка **Лимиты** на странице «Использование» показывает квоты, которые шлюз применяет к вашему трафику прямо сейчас: сколько каждого лимита израсходовано, когда окно обнулится и — для недельного и месячного бюджетов — кнопку сброса. Раздел всегда показывает ваши личные лимиты, а администратор может дополнительно выбрать любого пользователя в списке над карточкой.

![Квоты на странице использования](../assets/usage/usage-quotas.png)

## Карточки лимитов { #the-limit-cards }

На каждой карточке — израсходовано / лимит, полоса прогресса и обратный отсчёт до сброса. Значок `?` поясняет окно карточки.

| Карточка  | Окно                                                                                          | Сброс                                             |
| --------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| **RPM**   | запросов в минуту — скользящее 60-секундное окно.                                              | Непрерывно — старые запросы выходят из окна.       |
| **TPM**   | токенов в минуту — то же скользящее окно, счёт в токенах.                                      | Непрерывно.                                        |
| **Неделя** | токены за скользящие 7 дней — общий бюджет всех ваших API-ключей и сессий интерфейса.          | Непрерывно — по мере выхода из окна недельной давности. |
| **Месяц**  | токены за календарный месяц.                                                                   | На границе месяца по часовому поясу деплоя.        |

При исчерпании лимита шлюз отклоняет запросы с `429 Too Many Requests` — ещё до обращения к модельному инстансу — пока в окне не освободится место. Тело ответа называет сработавший лимит (`Too many requests per minute`, `Monthly token quota limit reached,
reset in usage overview` or `Too many concurrent requests for this model`),
а скользящие и календарные окна несут заголовок `Retry-After` с числом секунд до освобождения окна.

RPM и TPM защищают от коротких всплесков; недельный и месячный бюджеты ограничивают устойчивое потребление. Запрос расходует все окна, к которым имеет отношение: трафик ваших API-ключей и сессий интерфейса расходует один и тот же общий бюджет пользователя.

## Конкурентность по моделям { #concurrency-by-model }

Таблица под карточками показывает готовые (ready) модели, доступные вам, — сначала самые загруженные: сколько ваших собственных запросов к каждой модели выполняется прямо сейчас и действующий лимит для этой модели — администраторское переопределение, если оно задано, иначе дефолт деплоя. Модель, у которой счётчик выполняющихся запросов упёрся в лимит, — источник отклонений `429 Too Many Concurrent Requests`.

## Одновременные запросы к модели { #model-concurrency }

Помимо оконных лимитов и бюджетов шлюз ограничивает, сколько ваших запросов — по всем вашим API-ключам и сессиям — может одновременно выполняться на одной модели. Дефолт деплоя — **2**: пока два запроса к модели ещё выполняются, третий параллельный запрос к той же модели отклоняется с `429 Too Many Requests`, пока один из них не завершится. Слот освобождается сразу по завершении запроса — ждать сброса окна не нужно, поэтому такие отклонения не несут заголовка `Retry-After`.

Модели считаются по отдельности: выполняющийся запрос к одной модели не блокирует запросы к другим. На администраторов этот лимит не действует.

Дефолт и лимиты по отдельным моделям задаёт администратор в настройках вашей учётной записи. Модель без явного переопределения следует дефолту деплоя, а переопределение `0` полностью снимает ограничение для этой модели.

## Откуда берутся числа { #where-the-numbers-come-from }

- **Дефолты деплоя** — задаёт администратор для всех: RPM, TPM, месячные токены и лимит одновременных запросов на модель. Незаданный дефолт означает, что окно такого рода не лимитируется.
- **Лимиты пользователя** — недельный и месячный бюджеты токенов, а также RPM и TPM, которые администратор задаёт вашей учётной записи; общие для всех ваших ключей и сессий.
- **Квоты групп** — те же поля на уровне группы (администратор задаёт их на странице «Группы», кнопка «Управлять лимитами»). Для каждого поля независимо: явный лимит вашей учётной записи выигрывает; иначе применяется наименьшее значение среди ваших групп; иначе — дефолт деплоя. См. [Group Quotas](rate-limiting.md#group-quotas).

Это развёртывание использует следующие дефолты (администраторы правят их на вкладке «Лимиты», см. [Редактирование дефолтов деплоя](#editing-the-deployment-defaults)):

| Окно       | Дефолт                                                                 |
| ---------- | ---------------------------------------------------------------------- |
| RPM        | 10 запросов / минуту                                                     |
| TPM        | 768 000 токенов / минуту                                               |
| Месяц      | 100 000 000 токенов на пользователя                                    |
| Неделя     | без дефолта — лимит только для учётных записей с явным недельным бюджетом |
| Конкурентность | 2 запроса на модель                                                  |

Внутреннее устройство — конфигурация шлюза, дефолты, поведение при сбоях и метрики — описано в [Rate Limiting](rate-limiting.md).

## Редактирование дефолтов деплоя { #editing-the-deployment-defaults }

Администраторы правят дефолты деплоя — RPM, TPM, месячный бюджет токенов и лимит одновременных запросов на модель — на вкладке «Использование» → «Лимиты» (**Дефолтные лимиты деплоя**). Пустое поле означает «наследовать значение из конфиг-файла сервера»; конкурентность `0` полностью отключает лимит. Сохранение доезжает до шлюза на следующем проходе реконсилера (в течение минуты), без рестарта.

## Свободные окна { #free-windows }

Та же форма публикует **свободное окно** деплоя: ежедневный интервал времени (который может переходить через полночь) плюс полностью свободные дни; значения хранятся в UTC. Пока расписание действует, шлюз полностью приостанавливает лимиты — каждый запрос пропускается, слоты конкурентности не занимаются, счётчики лимитов замирают.

Запрос, **начатый** внутри окна, бесплатен целиком — даже если он продолжает стримиться после конца окна; начатый снаружи остаётся полностью лимитируемым. Статистика использования и отчёты собираются как обычно — останавливается только учёт для лимитов.

Пока окно активно, карточка «Лимиты» показывает бейдж **Свободное время**, чтобы замороженный счётчик не приняли за сломанный чтение. Форма показывает время в часовом поясе вашего браузера и конвертирует его в UTC при сохранении; дни следуют UTC.

## Сброс бюджета { #resetting-a-budget }

На карточках **Неделя** и **Месяц** есть кнопка **Сбросить**. Нажатие немедленно обнуляет счётчик окна: бюджет начинается заново, не дожидаясь естественной границы. Уже учтённое потребление остаётся в отчётах об использовании — сброс влияет только на счётчик квоты.

Для сброса нужно указать причину. Заметка сохраняется вместе с нажатием — кто, когда и зачем, — поэтому по аудиту видно, почему бюджет начался заново.

!!! note

    Сброс действует только на недельный и месячный бюджеты. RPM, TPM и лимит одновременных запросов короткоживущи: счётчики освобождаются сами — по мере выхода запросов из окна или их завершения.

### Квота сбросов { #reset-quota }

На каждое окно приходится два бесплатных сброса. Квота «плавает» вместе с самими нажатиями: два сброса в течение одной недели делают следующий доступным через неделю после первого нажатия, а не с ближайшей календарной границы. Когда оба израсходованы, кнопка становится неактивной, пока самое старое нажатие не выйдет из окна, — при наведении на неактивную кнопку показывается дата, когда сброс снова станет доступен.

Администраторы квотой не ограничены: администратор может сбросить бюджет в любой момент — свой или чужой, — и нажатия администратора не расходуют два бесплатных сброса пользователя.
