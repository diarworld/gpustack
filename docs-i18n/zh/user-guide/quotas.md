# 配额 { #quotas }

「Usage」页面的 **Limits** 标签页显示网关当前对你的流量执行的配额：每种额度已用多少、每个窗口何时重置，周预算和月预算还带有重置按钮。该区域始终只显示你自己的限额，管理员还可以通过卡片上方的选择器指定任意用户。

![Usage quotas](../assets/usage/usage-quotas.png)

## 限额卡片 { #the-limit-cards }

每张卡片包含「已用 / 上限」读数、进度条和重置倒计时。卡片上的 `?` 图标解释其窗口含义。

| 卡片      | 窗口                                                                                   | 重置                                       |
| --------- | -------------------------------------------------------------------------------------- | ------------------------------------------ |
| **RPM**   | 每分钟请求数 — 60 秒滑动窗口。                                                          | 连续进行，最旧的请求逐渐移出窗口。          |
| **TPM**   | 每分钟 token 数 — 同样的滑动窗口，按 token 计数。                                       | 连续进行。                                  |
| **周**    | 滚动 7 天窗口内的 token，由你所有 API 密钥和界面会话共享。                               | 连续进行，一周前的用量逐渐移出窗口。        |
| **月**    | 自然月内的 token。                                                                      | 在部署时区的月份边界重置。                  |

达到上限后，后续请求会在网关处被以 `429 Too Many Requests` 拒绝 — 尚未到达模型实例 — 直到窗口重新腾出空间。拒绝响应的正文会指明触发的是哪个限制（例如 `Too many requests per minute`、`Monthly token quota limit reached, reset in usage overview` 或 `Too many concurrent requests for this model`），滑动窗口和日历窗口还会携带 `Retry-After` 头，标示窗口释放前的秒数。

RPM 和 TPM 防御短时突发；周预算和月预算限制持续消耗。一个请求会计入它涉及的所有窗口：你的 API 密钥流量和界面会话流量消耗的是同一个用户级额度。

## 各模型并发情况 { #concurrency-by-model }

卡片下方的表格按忙碌程度排列你可用的就绪（ready）模型：每个模型当前正在运行的、属于你自己的请求数，以及该模型的有效上限 — 若管理员设置了模型级覆盖值则为其，否则为部署默认值。运行数顶到上限的模型，正是 `429 Too Many Concurrent Requests` 拒绝的来源。

## 每模型并发限制 { #model-concurrency }

除速率和预算窗口外，网关还限制你的请求 — 跨所有 API 密钥和会话 — 在同一模型上同时运行的数量。部署默认值为 **2**：当对某模型的两个请求仍在运行时，向同一模型发起的第三个并行请求会被 `429 Too Many Requests` 拒绝，直到其中一个结束。请求一结束槽位立即释放，无需等待任何窗口，因此这类拒绝不携带 `Retry-After` 头。

每个模型单独计数：对某个模型的进行中请求不会阻塞对其他模型的请求。管理员不受此限制。

默认值和各模型的覆盖值由管理员在你的账户上设置。未显式覆盖的模型沿用部署默认值，覆盖值 `0` 表示对该模型完全不限制。

## 数字的来源 { #where-the-numbers-come-from }

- **部署默认值** — 由管理员为所有人设置：RPM、TPM、每月 token 以及每模型并发上限。未设置的默认值表示该类窗口不受限。
- **用户级限额** — 管理员在你的账户上设置的周度和月度 token 预算，以及 RPM 和 TPM，由你的所有密钥和会话共享。

本部署使用以下默认值（管理员可在「Limits」标签页编辑，见[编辑部署默认限额](#editing-the-deployment-defaults)）：

| 窗口   | 默认值                                         |
| ------ | ---------------------------------------------- |
| RPM    | 每分钟 10 个请求                                |
| TPM    | 每分钟 768,000 个 token                        |
| 月     | 每个用户每月 100,000,000 个 token              |
| 周     | 无默认值 — 仅限制设置了显式周度预算的账户      |
| 并发   | 每模型 2 个请求                                 |

内部机制 — 网关配置、默认值、故障行为和指标 — 见 [Rate Limiting](rate-limiting.md)。

## 编辑部署默认限额 { #editing-the-deployment-defaults }

管理员在「Usage」→「Limits」标签页（**部署默认限额**）编辑部署默认值 — RPM、TPM、每月 token 预算和每模型并发上限。留空表示"继承服务器配置文件的值"；并发填 `0` 表示完全关闭上限。保存后会在下一次调和（一分钟内）应用到网关，无需重启。

## 免费时段 { #free-windows }

同一表单还会发布部署范围的**免费时段**：每日时间段（可跨午夜）加上整天免费的日子，以 UTC 存储。时段生效期间，网关完全暂停限速 — 所有请求都放行，不占用并发槽位，限额计数器冻结。

在时段**内开始**的请求整个生命周期都免费 — 即使它持续流式输出超过窗口结束；在时段外开始的请求仍正常受限。用量统计和报表照常收集 — 停止的只是限额计数。

时段生效时，「Limits」卡片会显示**免费时段**徽标，以免把冻结的计数器误认为读取故障。表单按浏览器本地时区显示和输入时间，保存时转换为 UTC；星期按 UTC 计。

## 重置预算 { #resetting-a-budget }

**周**和**月**卡片带有**Reset**按钮。按下后该窗口的计数器立即归零：预算无需等待自然边界即可重新开始。已记录的用量仍保留在用量报表中 — 重置只影响配额计数器。

重置时必须填写原因。备注与这次按下一起保存 — 谁、何时、为什么 — 因此审计记录能说明每个预算为何重新开始。

!!! note

    重置仅适用于周预算和月预算。RPM、TPM 和每模型并发上限都是短效的 — 请求移出窗口或完成后，计数器会自行释放。

### 重置次数 { #reset-quota }

每个窗口有两次免费重置。次数随按下动作本身“浮动”：一周内重置两次后，下一次要到第一次按下一周后才可用，而不是下一个日历边界。两次都用完后按钮被禁用，直到最早一次按下移出窗口 — 悬停禁用的按钮会显示下次重置可用的日期。

管理员不受次数限制：管理员可以随时重置预算 — 自己的或其他用户的 — 且管理员的按下不会消耗用户自己的两次免费额度。
