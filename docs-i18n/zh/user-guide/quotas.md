# 配额 { #quotas }

「Usage」页面「Overview」中的 **Limits** 区域显示网关当前对你的流量执行的配额：每种额度已用多少、每个窗口何时重置，周预算和月预算还带有重置按钮。该区域始终只显示你自己的限额，管理员看到的也是其本人的限额。

![Usage quotas](../assets/usage/usage-quotas.png)

## 限额卡片 { #the-limit-cards }

每张卡片包含「已用 / 上限」读数、进度条和重置倒计时。卡片上的 `?` 图标解释其窗口含义。

| 卡片      | 窗口                                                                                   | 重置                                       |
| --------- | -------------------------------------------------------------------------------------- | ------------------------------------------ |
| **RPM**   | 每分钟请求数 — 60 秒滑动窗口。                                                          | 连续进行，最旧的请求逐渐移出窗口。          |
| **TPM**   | 每分钟 token 数 — 同样的滑动窗口，按 token 计数。                                       | 连续进行。                                  |
| **周**    | 滚动 7 天窗口内的 token，由你所有 API 密钥和界面会话共享。                               | 连续进行，一周前的用量逐渐移出窗口。        |
| **月**    | 自然月内的 token。                                                                      | 在部署时区的月份边界重置。                  |

达到上限后，后续请求会在网关处被以 `429 Too Many Requests` 拒绝 — 尚未到达模型实例 — 直到窗口重新腾出空间。

RPM 和 TPM 防御短时突发；周预算和月预算限制持续消耗。一个请求会计入它涉及的所有窗口：你的 API 密钥流量和界面会话流量消耗的是同一个用户级额度。

## 按密钥的每日用量 { #per-key-daily-usage }

卡片下方的表格列出你的每个 API 密钥及其每日 token 配额 — 密钥自身的每日限额或部署默认值 — 并显示当天的「已用 / 上限」读数。每日窗口与日历对齐，在部署时区的午夜重置。

## 每模型并发限制 { #model-concurrency }

除速率和预算窗口外，网关还限制你的请求 — 跨所有 API 密钥和会话 — 在同一模型上同时运行的数量。部署默认值为 **1**：当一个对某模型的请求仍在运行时，向同一模型发起的第二个并行请求会被 `429 Too Many Requests` 拒绝，直到第一个请求结束。请求一结束槽位立即释放，无需等待任何窗口。

每个模型单独计数：对某个模型的进行中请求不会阻塞对其他模型的请求。管理员不受此限制。

默认值和各模型的覆盖值由管理员在你的账户上设置。未显式覆盖的模型沿用部署默认值，覆盖值 `0` 表示对该模型完全不限制。

## 数字的来源 { #where-the-numbers-come-from }

- **部署默认值** — 由管理员为所有人设置：RPM、TPM、每日和每月 token。未设置的默认值表示该类窗口不受限。
- **用户预算** — 管理员在你的账户上设置的周度和月度 token 预算，由你的所有密钥和会话共享。
- **密钥限额** — 单个密钥上的 RPM、TPM 和每日 token 限额。未设置的字段继承部署默认值。

本部署使用以下默认值：

| 窗口   | 默认值                                         |
| ------ | ---------------------------------------------- |
| RPM    | 每分钟 10 个请求                                |
| TPM    | 每分钟 768,000 个 token                        |
| 天     | 每个 API 密钥每天 10,000,000 个 token          |
| 月     | 每个用户每月 100,000,000 个 token              |
| 周     | 无默认值 — 仅限制设置了显式周度预算的账户      |

内部机制 — 网关配置、默认值、故障行为和指标 — 见 [Rate Limiting](rate-limiting.md)。

## 重置预算 { #resetting-a-budget }

**周**和**月**卡片带有**Reset**按钮。按下后该窗口的计数器立即归零：预算无需等待自然边界即可重新开始。已记录的用量仍保留在用量报表中 — 重置只影响配额计数器。

重置时必须填写原因。备注与这次按下一起保存 — 谁、何时、为什么 — 因此审计记录能说明每个预算为何重新开始。

!!! note

    重置仅适用于周预算和月预算。RPM、TPM 和密钥每日配额是短窗口，会自行释放。

### 重置次数 { #reset-quota }

每个窗口有两次免费重置。次数随按下动作本身“浮动”：一周内重置两次后，下一次要到第一次按下一周后才可用，而不是下一个日历边界。两次都用完后按钮被禁用，直到最早一次按下移出窗口 — 悬停禁用的按钮会显示下次重置可用的日期。

管理员不受次数限制：管理员可以随时重置预算 — 自己的或其他用户的 — 且管理员的按下不会消耗用户自己的两次免费额度。
